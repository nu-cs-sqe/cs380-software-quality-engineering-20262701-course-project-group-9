# Player BVA

Player stores setup data. IDs/names are validated or generated by its collaborators. No eliminated state exists yet.

| ID | Public methods | State/input | Expected | Implemented |
| --- | --- | --- | --- | --- |
| P01 | Player(int,String), getId(), getName() | Initialize players 0 and 1 named Alice/Bob | IDs and names preserved in order | Yes, PlayerInitializerTest |
| P02 | Player(int,String), isAlive(), getHand() | New player | Alive, empty hand | Yes, PlayerInitializerTest |
| P03 | getHand() | Add to returned empty hand | Stored hand remains empty | Yes, PlayerInitializerTest.returnedHandShouldNotChangePlayer |
| P04 | Player(int,String,List), getHand() | Eight cards; clear source and returned hand | Stored eight-card hand unchanged | Yes, GameSetupTest.playerCopiesStartingHand |
| P05 | Player(int,String,List), getHand() | Empty list | Empty stored hand | Yes, GameSetupTest.playerCopiesStartingHand |
| P06 | getId(), getName(), isAlive(), getHand() | Game setup with 2–5 players | Correct alignment and alive/eight-card state | Yes, GameSetupTest.initializesRealComponentsTogether |

Negative direct IDs/null names are not validated by this class and are outside the setup-generated input contract. Future gameplay mutations require new boundary analysis, particularly eliminating a player and changing a hand.
